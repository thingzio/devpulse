# PDF Report Generation — Design

**Date:** 2026-04-02
**Status:** Draft

## Goal

Add an on-demand "Download PDF" button to the repo detail view that generates a single-page PDF report containing all chart panels, tables, and insights for one repository.

## Trigger

A "Download PDF" button in the top bar, next to the Period selector. The button is disabled unless a single repo is selected (hidden or disabled at org/all-repos scope).

## User Flow

1. User navigates to a single-repo view (e.g., `?o=org&r=repo`)
2. Button becomes enabled
3. User clicks "Download PDF"
4. Loading spinner appears on the button
5. All tab charts render into a hidden off-screen container
6. Charts are extracted via `canvas.toDataURL('image/png')`
7. PDF is assembled and downloaded as `devpulse-org-repo-YYYY-MM-DD.pdf`
8. Hidden container is cleaned up, spinner removed

## PDF Layout

### Header
- Repository name (`org/repo`)
- Period (e.g., "6 months")
- Generation date

### Sections (in order, matching tab structure)

Each section has a bold section header.

#### 1. Health
- Bus Factor and Pony Factor as labeled text values
- Health activity sparkline chart
- Repository Status metadata (stars, forks, issues, language, license) as text block
- Stars Trend chart
- Forks Trend chart

#### 2. Activity
- Time-based events chart (left chart)
- Contributor activity chart (right chart)
- Contributor retention chart
- Container activity chart (if data exists)

#### 3. Velocity
- PR ratio chart
- Time to merge chart
- Time to close chart
- Release cadence chart
- Release downloads chart
- Release downloads by tag chart
- Change failure rate chart

#### 4. Quality
- Review latency chart
- PR size distribution chart
- Time to first response chart
- Issue ratio chart

#### 5. Community
- Reputation chart
- Forks and activity chart
- Contributor funnel chart
- Contributor momentum chart

#### 6. Insights
- LLM-generated insights rendered as formatted text blocks
- Each insight category as a sub-header with its content below

### Chart Layout
- Two charts side-by-side per row where they fit (landscape-ish)
- Full-width for charts that need it (time series with many data points)
- Tables rendered via jsPDF autoTable plugin

### Footer
- Page numbers
- "Generated by DevPulse" attribution

## Technical Approach

### Render-All-Then-Capture (Client-Side Only)

No server-side changes required.

1. Create a hidden off-screen `<div>` with cloned `<canvas>` elements
2. For each tab, invoke the existing `loadTabCharts()` data-fetching functions targeting the cloned canvases
3. Wait for all fetch + render cycles to complete
4. Extract each canvas via `toDataURL('image/png')`
5. Build PDF using jsPDF
6. For scalar values (Bus Factor, Pony Factor, repo metadata): read from existing DOM elements
7. For tables (Repo Overview): read from existing DOM table or re-fetch from API
8. For insights: fetch from existing insights API endpoint
9. Clean up hidden container

### Dependencies

Added via CDN in `header.html` (matching existing pattern for Chart.js):

| Library | Size | Purpose |
|---------|------|---------|
| jsPDF | ~280KB UMD | PDF generation |
| jspdf-autotable | ~45KB | Table rendering in PDF |

No server-side dependencies. No build step changes.

### Code Changes

| File | Change |
|------|--------|
| `pkg/server/templates/home.html` | Add "Download PDF" button in top bar |
| `pkg/server/templates/header.html` | Add jsPDF + autoTable CDN script tags |
| `pkg/server/static/js/app.js` | Add PDF generation logic (~200-300 lines) |
| `pkg/server/static/css/style.css` | Button styling for PDF download button |

### Key Implementation Details

- **Chart rendering**: Clone canvas elements at fixed dimensions (e.g., 800x400) for consistent PDF output regardless of viewport
- **Data fetching**: Reuse existing API endpoints (`/api/data/*`) — same calls the dashboard makes
- **Async orchestration**: Use `Promise.all` to fetch all chart data in parallel, then render sequentially
- **Error handling**: If a chart fails to load, include a "No data available" placeholder in the PDF rather than failing the entire export
- **Button state**: Disabled + spinner while generating; re-enabled on completion or error

## Scope Exclusions

- Events tab (raw event log — not useful in a summary PDF)
- Server-side PDF generation
- Scheduled/automated reports (future feature)
- Multi-repo comparison PDFs

## Design Decisions

1. **Chart dimensions**: Fixed two-up layout (two charts per row, ~380x220 points each)
2. **Theme**: Always light theme in PDF for print-friendliness, regardless of user's current theme
3. **Large tables**: Paginate within the PDF if Repo Overview exceeds one page
